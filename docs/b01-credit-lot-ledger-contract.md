# B-01 credit-lot ledger contract

OpenReel represents purchased or granted points as immutable, account-scoped lots. Each lot records its general/model-specific scope, original and remaining points, grant/expiry instants and the quote that authorized its shape.

`planCreditConsumption` is deliberately a plan, not a debit. It excludes expired and incompatible model lots, orders eligible lots by earliest expiry, and returns `executable=false`, `paymentConnected=false` and `requiresHumanGate=true`. It never creates an order, grants points, changes a balance or calls a payment/provider service.

`reconcileCreditLots` separates granted, consumed, unexpired spendable and expired-but-unconsumed points. Both operations fail closed on account-scope escape, duplicate lot ids, invalid timestamps, unsafe integer totals, impossible balances and unknown/accessor-backed fields.

`createCreditLedgerStore` provides a local, payment-disconnected application boundary. It persists lots and operation receipts with atomic temp-file replacement plus file and directory sync, binds each operation id to the complete plan fingerprint, applies only against an exact expected revision, and returns an immutable replay receipt after restart without debiting twice. Initialization and debit application also acquire an atomic sibling-directory lock before reading or replacing state, so separate local processes cannot both pass the same revision check. A live or crash-abandoned lock fails closed with `CREDIT_LEDGER_LOCKED`; it is never guessed stale or automatically removed. Stale revisions, changed idempotency payloads, corrupt state, missing lots, insufficient remaining points and debit-total drift also fail closed.

Abandoned-lock recovery is an explicit two-step operator protocol. `inspectLock()` validates the complete v2 owner record and returns its SHA-256 fingerprint without changing state. `recoverLock()` requires that exact fingerprint, atomically creates an exclusive recovery claim inside the canonical lock directory, revalidates the owner bytes, removes only the claimed lock and syncs the parent directory. The canonical lock path therefore remains present until successful removal; a crashed recoverer leaves both the lock and its claim in place, so ledger mutations continue to fail closed. Missing, malformed, concurrently claimed, replaced or drifted ownership fails closed; elapsed time is never treated as proof that a lock is abandoned.

This closes a local durable-debit, process-exclusion and identity-bound recovery increment only. The store is not a distributed database, and an operator must independently establish that the inspected owner is abandoned before invoking recovery. It is not connected to order creation, recharge, payment collection or real point grants. Authenticated LibTV personal-ledger comparison and payment-provider staging evidence remain outside this evidence and require their respective gates.

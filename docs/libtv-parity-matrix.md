# LibTV ↔ OpenReel capability matrix

Version: 4.4 · Evidence refreshed: 2026-08-13 · Project status: ongoing

This is a product comparison and evidence ledger, not a claim that LibTV internals are known or copied. Public product pages prove advertised surface area only; local tests prove OpenReel behavior only; neither proves production parity.

## Evidence policy and sources

- `F1` first-party public: LibTV home page, <https://www.liblib.tv/> (retrieved 2026-08-06). It advertises a canvas, Skills, community examples, membership and credits.
- `F2` first-party public: LibTV CLI page, <https://www.liblib.tv/zh/cli> (retrieved 2026-08-06). It advertises CLI installation, web login and Agent integration.
- `F3` first-party source: `libtv-labs/libtv-skills` README, <https://github.com/libtv-labs/libtv-skills> (retrieved 2026-08-06). It documents session creation/query, project switching, image/video upload and result download via authenticated API.
- `A1` authenticated observation supplied by the project owner on 2026-08-04. This is retained as historical product observation, not implementation evidence.
- `A2` authenticated read-only CLI walkthrough on 2026-08-07, summarized in `libtv-authenticated-evidence-2026-08-07.md`. No generation, payment or mutation was performed.
- `L1` OpenReel local suite: `npm test`, 140/140 passed on 2026-08-13; dependency audit reported 0 vulnerabilities, secret scan passed, bounded 200-request reliability qualification passed, and the 10-file release manifest rejected tampering.
- `L2` OpenReel repository evidence: named source, test, smoke or operations artifact. A local implementation is not a production claim.
- `U` unknown or unverified. Third-party search results may identify research leads but do not close a row.

## Current decision

OpenReel is **not project complete**. CAP-02 and CAP-08 are accepted locally, while CAP-03 through CAP-07, CAP-09 through CAP-10, and CAP-12 through CAP-14 retain provider, real-media, authenticated-team, operational or human-gated gaps. The terminal rule lives in `project-completion-contract.md`; the execution sequence lives in `libtv-parity-backlog.json`.

Phone login may be used only after an operator supplies the one-time code at a human gate. No paid generation, subscription, public publish, production deployment or credential change is authorized by this matrix.

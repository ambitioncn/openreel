## 2. 产品愿景

OpenReel 是面向个人创作者、小团队和商业内容生产者的 AI 原生视频工作空间。用户可以从一句创意、一个产品页面或已有素材开始，让 Agent 协助完成策划、脚本、分镜、素材生成、配音、配乐、字幕、时间线合成、审阅和导出。

OpenReel 的目标不是提供一组彼此孤立的模型按钮，而是把多模型能力组织成一个可理解、可控制、可恢复、可追溯的完整生产流程。

长期愿景是：让一个不熟悉模型参数和视频工具的用户，也能像与创作搭档合作一样，在一个项目空间中稳定产出可用视频；专业用户仍能检查和修改每个中间结果，而不是被黑盒式“一键生成”绑架。

## 3. 产品定位

### 3.1 一句话定位

从创意或产品信息到可播放成片的 AI 视频创作与生产工作空间。

### 3.2 核心价值

1. **完整闭环**：从创意、策划、分镜到真实图片、视频、音频和最终 MP4，不要求用户手动拼接多个工具。
2. **Agent 协作**：同一套项目、预算、版本和进度机制同时服务浏览器用户与 Agent。
3. **过程可控**：关键付费步骤有报价和确认；每个镜头、中间素材和生成阶段可查看、失败可恢复。
4. **版本可信**：素材、故事、分镜、时间线和成片绑定同一项目版本，避免把旧素材误当成本轮生成结果。
5. **模型可替换**：围绕能力和参数路由模型，不让产品体验依赖单一厂商。
6. **生产可运营**：身份隔离、预算硬限制、持久化、备份恢复、回滚和证据留存进入产品基础设施。

### 3.3 竞争边界

- 主要对标对象是 LibTV 等闭源 AI 视频生产平台的产品体验、Agent 创作闭环和商业化能力。
- OpenReel 不以复制竞品界面或推断其内部实现为目标。
- OpenReel 不做 ComfyUI 替代品。ComfyUI 等节点式基础设施可以成为兼容或集成对象，但不是产品定位本身。
- 模型数量不是核心胜负手；可执行能力、生成质量、工作流完整性、可控性和可复现证据更重要。

## 4. 目标用户

### 4.1 核心用户

#### A. 轻量商业内容创作者

- 需要持续制作商品展示、品牌短片、社交媒体短视频；
- 有明确创意或产品链接，但缺少完整制作团队；
- 关心出片速度、成本、可修改性和可发布性。

#### B. 独立视频创作者

- 制作故事短片、预告片、艺术视频、纪录式内容或账号内容；
- 希望控制脚本、镜头、角色/场景一致性、配音、音乐与字幕；
- 不满足于单次黑盒生成，希望保留创作过程和素材资产。

#### C. 小型内容团队

- 需要项目化管理多条视频及其版本和素材；
- 需要明确的审核、成本和生产状态；
- 团队协作能力是后续方向，当前不作为已完成的终态承诺。

#### D. Agent 与自动化开发者

- 希望通过稳定 API/CLI/Skill 驱动视频项目；
- 需要幂等执行、预算门禁、进度查询、失败恢复和结果溯源；
- 不希望为不同入口维护两套业务语义。

### 4.2 暂非优先用户

- 需要完整专业 NLE（非线性编辑）全部能力的影视后期团队；
- 只想调用裸模型 API、无需项目与创作流程的开发者；
- 需要本地训练、节点插件生态和底层推理调度的 ComfyUI 核心用户；
- 需要无人审核的大规模自动发布农场。

## 5. 用户问题

1. AI 视频工具分散，用户需要在文本、图片、视频、配音、音乐和剪辑产品之间搬运内容。
2. 单次生成缺少项目上下文，角色、产品、场景和镜头难以保持连续。
3. “一键成片”常隐藏过程，失败后不知道停在哪一步，也无法只重做失败镜头。
4. 模型参数、费用和可用能力复杂，新用户不知道如何选择。
5. 中间素材与最终视频缺少版本绑定，容易混用旧资产或无法证明成片来源。
6. 从成片到平台发布仍需多处账号连接、格式检查和状态追踪。
7. Agent 自动化若没有预算、身份、幂等和确认边界，会带来费用与外部发布风险。

## 6. 核心使用场景

### 6.1 从一句创意生成短视频

用户输入创意，系统创建新项目或要求明确选择项目，使用真实文本模型生成脚本和分镜。用户审阅后确认商业生成报价，系统按镜头生成首帧与视频，并完成配音、字幕、音乐、时间线和 MP4 合成。

成功标准：用户能够看到阶段进度和成本，获得与当前项目版本一致、可播放且带音频的 MP4。

### 6.2 从产品页面生成商业视频

用户提交公开 HTTPS 产品页。服务端在 SSRF、DNS、重定向、类型、大小和超时约束下抓取内容，真实理解模型生成带原文证据的产品信息，再进入创意与视频生产流程。

成功标准：结论可追溯到抓取来源和直接引用；不把浏览器凭据、内网资源或未经证实的模型改写当作产品事实。

### 6.3 分镜级审阅和返工

用户查看每个镜头的视觉描述、参考素材、首帧和视频结果，只重做某个镜头，而不丢失已接受的其他镜头及其版本关系。

成功标准：返工范围明确，旧结果保留，时间线合并后仍绑定正确版本。

### 6.4 复用角色、产品、场景和历史资产

用户从项目资产库选择已有素材或显式复制到新项目。系统记录来源和复用关系，不把复用素材伪装成本轮新生成。

成功标准：用户能搜索、筛选、预览和复用资产；跨项目复用具有明确 provenance。

### 6.5 Agent 驱动完整生产

Agent 使用同一业务边界完成 prepare、报价确认、execute、progress 和结果获取。浏览器与 Agent 共享项目、预算、版本、任务状态和失败恢复机制。

成功标准：执行可幂等恢复，关键步骤可观察，Agent 不能绕过身份、预算、确认和版本校验。

### 6.6 审阅后发布到内容平台

用户连接目标平台账号，选择已验收视频，确认标题、文案、隐私与平台参数后进入发布队列，并查看上传、处理、成功、失败或远端状态未知等状态。

成功标准：OAuth 凭据仅保存在服务端；不盲目重试状态不明的外部写操作；每次真实发布都由明确的用户动作触发。

当前边界：发布框架和部分平台适配器已经实现；各平台真实可用性仍取决于开发者应用审核、scope、凭据、账号资格和逐平台生产验收，不能统一宣称已上线。

## 7. 产品原则

1. **新创意默认新作品**：除非用户明确选择现有项目，不得覆盖已有创作。
2. **先计划、后付费**：付费模型调用前显示范围、报价和硬预算边界。
3. **失败关闭**：身份、版本、证据、预算或外部状态不确定时停止，不伪造成功。
4. **局部可重做**：失败或不满意时优先重做单镜头/单阶段，不重复整条昂贵链路。
5. **事实与生成分离**：产品事实需要来源证据；创意改写必须明确属于生成内容。
6. **入口一致**：浏览器、Agent、API 和 CLI 使用同一项目与执行合同。
7. **证据优先**：已配置、已编码、测试通过、生产成功和人工接受是不同状态。
8. **人控制外部动作**：账号授权、付费确认、发布和破坏性操作保持显式边界。

## 8. 信息架构

### 8.1 全局层

- 首页/工作台：最近项目、新建作品、模板与学习入口；
- 项目列表：搜索、打开、重命名、归档；
- 账号与连接：模型/平台能力状态、内容平台账号连接；
- 任务与发布：生成任务、发布队列、错误和恢复入口；
- 资产库：跨项目可发现资产与显式复用；
- 用量与预算：报价、预留、结算、硬上限和历史证据；
- 设置与运维：个人设置、权限、安全与系统状态。

### 8.2 项目层

- 创意简报：一句话创意、产品 URL、目标受众、平台、时长和风格；
- 故事/脚本：剧情结构、旁白、字幕候选；
- 分镜：场景、镜头、时长、视觉提示、角色/产品/场景引用；
- 画布：可视化节点、连线、分组、运行和历史；
- 素材：上传与生成的图片、视频、语音、音乐和音效；
- 时间线：视频轨、音频轨、字幕、裁切、排序与合成；
- 预览与导出：成片预览、版本、下载和证据；
- 发布：目标平台、文案、隐私、预检、确认和状态。

### 8.3 核心对象关系

`用户/租户 → 项目 → 故事版本 → 分镜版本 → 镜头 → 生成任务/素材 → 时间线 → 渲染版本 → 发布任务`

所有生成和发布对象必须保留身份、项目、版本、模型/适配器、成本、输入摘要和结果摘要等必要溯源信息。

## 9. 功能范围

### 9.1 已验收核心基线

- 注册、登录、安全会话与租户隔离；
- 项目创建、选择、重命名、归档与持久化；
- 结构化故事、分镜、镜头和版本身份；
- 画布节点、连线、分组、执行、进度、结果与历史；
- 图片、视频、音频上传、索引、筛选、下载和显式复用；
- 能力驱动的模型目录、参数校验和路由；
- 真实文本规划、Seedream 图片、Seedance 视频、Qwen TTS、已审核音乐、中文字幕与 FFmpeg 合成链路；
- 生成报价、确认、费用预留、结算与账户硬上限；
- 按镜头生成、阶段进度、失败恢复和局部重做；
- H.264/AAC MP4 预览与导出；
- 产品 URL 安全抓取、真实理解模型和直接引用证据；
- Agent prepare/confirm/execute/progress 完整入口；
- CLI、版本化 API、模板和教程基础能力；
- 生产部署、健康检查、备份、隔离恢复和回滚证据。

### 9.2 已实现但仍受外部条件约束

- TikTok、抖音、Instagram、YouTube 的 OAuth、适配器、队列和状态框架；
- 平台连接入口、发布预检、显式确认、幂等与审计；
- 真实平台 OAuth 和发布验收。

这些能力必须逐平台标记为：`不可用`、`待配置`、`待审核`、`可连接`、`可发布`或`已验收`。没有开发者应用审批、正式凭据、所需 scope 和真实账号验收时，不得展示为已完全可用。

### 9.3 后续增强范围

- 更强的角色、产品和场景跨镜头一致性；
- 更高质量和更多规格的导出；
- 更成熟的时间线编辑和镜头级控制；
- 团队审阅、评论、角色权限与协作空间；
- 模板市场、品牌套件和批量变体；
- 更多模型供应商与智能路由；
- 生产级内容平台发布与数据回流；
- 面向 Agent 的稳定 SDK、Skill 与自动化配方。

## 10. 非目标

- 不复制或反向工程 LibTV 的私有实现；
- 不追求模型目录数量与竞品数字相等；
- 不做 ComfyUI、After Effects、Premiere 或完整专业 NLE 的替代品；
- 不在缺少证据时宣称画质、连续性或平台兼容性达到某竞品水平；
- 不允许 Agent 绕过费用、身份、版本、OAuth 或发布确认；
- 不默认自动发布，不建设未经审核的大规模内容灌发系统；
- 当前不把支付系统、订阅对账和 LibTV credits 对齐作为已承诺终态；
- 当前不把完整团队空间作为已承诺终态。

## 11. 商业模式

商业模式仍需真实用户与成本数据验证，当前采用以下产品假设：

### 11.1 建议模式

- **免费/体验层**：项目管理、基础编辑、有限本地或体验额度、带明确限制的预览导出；
- **创作者订阅**：更高项目/存储/并发额度、模板、品牌能力、优先队列和更高质量导出；
- **按量模型费用**：对第三方模型调用透明报价，按实际使用结算，设置账户硬上限；
- **团队方案（后续）**：共享资产、审批、角色权限、团队预算和审计；
- **开发者方案（后续）**：API/Agent 调用额度、批量任务、Webhook 和商业使用支持。

### 11.2 商业原则

- 订阅价值与模型成本分开表达，避免“无限生成”造成不可控成本；
- 用户确认前展示可理解的报价或上限；
- 失败、取消、预留释放和实际结算规则透明；
- 不在支付、退款、税务和配额系统完成前对外承诺正式收费产品；
- 优先验证用户是否愿意为“稳定出片与节省工作时间”付费，而不是为模型数量付费。

## 12. 关键指标

### 12.1 北极星指标

**每周成功完成并由用户接受的有效视频作品数。**

“有效视频作品”至少满足：由真实用户项目产生、可播放、通过必要的版本与素材校验，并被下载、保存、进入发布队列或明确标记为接受。

### 12.2 激活指标

- 新用户首次创建项目的比例；
- 首次会话内完成脚本和分镜的比例；
- 首次会话内到达报价/确认步骤的比例；
- 首次成功生成可播放 MP4 的比例与耗时。

### 12.3 创作漏斗

- 创意 → 脚本成功率；
- 脚本 → 分镜接受率；
- 分镜 → 首帧/视频生成成功率；
- 素材生成 → 合成成功率；
- 成片 → 下载/发布准备率；
- 各阶段退出、失败和局部重做比例。

### 12.4 质量与效率

- 单条被接受视频的总耗时与人工操作次数；
- 首次生成接受率、镜头重做率和整链重跑率；
- 单条被接受视频的模型成本；
- 字幕、音画同步、可播放性和版本一致性通过率；
- 角色/产品/场景连续性的人评得分。

### 12.5 留存与商业化

- D1、D7、D30 创作者留存；
- 每周活跃创作者和每位创作者完成作品数；
- 订阅转化、付费留存和毛利；
- 免费到付费的触发场景；
- 平台连接率、发布成功率和发布后回访率。

### 12.6 可靠性与安全

- 任务成功率、阶段失败率和恢复成功率；
- P50/P95 规划、生成和合成耗时；
- 重复扣费、超预算调用和跨租户访问事件数（目标为 0）；
- 状态不明外部写被盲目重试次数（目标为 0）；
- 备份、恢复和回滚演练通过率。

指标上线前应补齐匿名化、最小化的数据采集方案；不得为分析目的记录密钥、OAuth token、完整敏感输入或不必要的用户素材。

## 13. 路线图

### 阶段 A：产品基线收口（已完成）

- 新作品/版本边界；
- 真实文本规划与多模态生成；
- 音频、字幕、音乐和最终合成；
- 浏览器与 Agent 完整入口；
- 产品 URL 理解；
- 预算、证据、生产与恢复边界。

完成依据：V4-01～V4-07 生产证据包及 cp60 人工终态验收。

### 阶段 B：可用性与创作质量

- 以新用户为中心重构首屏、工作台和创作向导；
- 减少从创意到首条成片的认知负担和操作步骤；
- 加强镜头审阅、局部重做、连续性和失败解释；
- 修订 README、教程和产品内文案，使其与真实生产能力一致；
- 建立同源素材质量评测与人工接受标准。

### 阶段 C：平台发布闭环

- 以当前生产版本重新构建各平台候选，禁止激活过时 release；
- 完成开发者应用审核、最小 scope、凭据配置和账号连接；
- 按平台完成 OAuth、预检、私密/测试发布、状态对账和失败恢复；
- 优先选择一个平台完成端到端验收，再扩展到其他平台；
- 引入发布后结果回流，但不自动扩大外部写权限。

### 阶段 D：商业化验证

- 访谈并招募首批目标创作者；
- 验证定价、额度、成本透明度和付费意愿；
- 完成正式支付、退款、发票/税务适配和额度策略后再开放收费；
- 围绕有效作品数、接受率、单位成本和留存做产品迭代。

### 阶段 E：团队与生态

- 团队空间、共享资产、评论、审核和角色权限；
- 品牌套件、模板市场、批量变体和内容日历；
- 稳定 SDK、Agent Skill、Webhook 与第三方工作流集成；
- 在安全和质量边界成熟后探索受控的自动化发布。

## 14. 发布与状态表达

产品和文档必须使用以下状态词，避免把实现进度误写成用户能力：

- **设计中**：只有需求或方案；
- **本地实现**：代码存在，尚无生产证据；
- **测试通过**：自动化验收通过，尚无生产证据；
- **已部署**：生产版本包含该能力，但可能仍缺配置或外部授权；
- **可连接/可执行**：生产所需配置和权限已具备；
- **生产验收通过**：真实账号、真实路径和必要证据通过；
- **对用户开放**：已满足运营、安全、支持和产品发布要求。

平台适配、模型路由和付费能力不得仅因“配置项存在”就标记为可用。

## 15. 风险与待验证假设

1. 多模型成本和失败率是否允许形成可持续毛利；
2. 用户是否更重视一键速度，还是分镜级控制与可恢复性；
3. 真实生成质量能否稳定达到商业内容的接受阈值；
4. 平台开发者审核和 API 政策是否允许稳定发布闭环；
5. 小团队是否愿意为协作、品牌资产和审核功能付费；
6. Agent 自动化能否在不增加误操作风险的前提下显著提升产能；
7. 当前单机生产架构在用户增长后何时需要拆分任务、媒体和数据库服务。

每项假设应通过用户研究、产品数据或受控生产证据验证，不以竞品表述或内部推测替代。

## 16. 产品决策与变更机制

- 产品范围变更先更新本文档，再更新工程 backlog 和验收合同；
- 新能力必须定义用户价值、非目标、状态表达和验收证据；
- 生产部署、凭据、付费调用和外部发布继续遵循对应安全门禁；
- 阶段完成不能自动改写为项目或产品完成；
- 竞品研究只用于发现用户需求和体验差距，不作为 OpenReel 已实现或竞品内部事实的证明。

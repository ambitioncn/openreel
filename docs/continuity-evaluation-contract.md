# Continuity evaluation contract

Status: local contract only; no real-media result is claimed.

Each evaluated storyboard batch must retain the reviewed `continuityEntityUsages` snapshot for every shot and produce a JSON artifact with schema `openreel-continuity-evaluation/v1`. The artifact identifies the project, storyboard version, batch id, provider/model, generation parameters, ordered output asset ids, evaluator, evaluation time, and one score record per ordered shot.

`src/continuity-evaluation.js` is the credential-free, fail-closed validator for this artifact. It rejects unknown or missing fields, output/score ordering drift, duplicate identifiers, malformed score ranges and invalid artifact digests. Artifact kinds must be canonical identifiers, and artifact paths must be unique canonical relative paths without traversal, absolute-path, repeated-separator, or platform-dependent backslash forms. Every per-shot entity usage must retain the complete entity kind, name, positive version, non-empty attributes, valid locked-attribute set, ordered reference ids, and aligned reference provenance with canonical UTC timestamps. This prevents an empty or forged usage stub or an ambiguous artifact location from receiving a valid evidence fingerprint. Generation parameters and reference-provenance sources must be finite JSON data: values that JSON would omit or silently normalize, typed objects, and circular references are rejected. Every schema field must be an own property of a plain record rather than an inherited value. All record keys across the complete normalized evaluation graph are sorted before fingerprinting, so equivalent JSON objects retain the same identity regardless of caller insertion order. A structurally valid artifact receives a deterministic fingerprint, and its complete normalized object graph is recursively frozen so callers cannot mutate nested parameters, scores, artifacts, or provenance after fingerprinting.

`verifyContinuityArtifactFiles` adds the retained-byte verification step: it resolves every declared artifact below one caller-supplied artifact root, rejects missing, empty, and non-file targets, rejects symlinks that resolve outside that root, and opens the resolved target without following a replacement final symlink. It then verifies the actual opened file descriptor still resolves to the same in-root file before reading bytes. SHA-256 is computed as a bounded-memory stream from that descriptor, and device, inode, size, modification time, and change time must remain identical before and after the read. This closes path substitution and in-place concurrent-mutation windows, prevents an empty placeholder from qualifying as retained evidence, and requires the digest of the stable descriptor-bound bytes to match the evaluation exactly. A successful result binds byte size and digest to the evaluation fingerprint. This remains a local evidence-integrity check; it does not prove that artifacts came from a real provider call or replace the separately gated real-media generation and human visual review.

Every score is an integer from 1 (unacceptable) to 5 (strong match) for:

- `identity`: locked character or product attributes remain recognizable.
- `scene`: locked environment, lighting, palette, and spatial anchors remain consistent.
- `referenceAdherence`: the output follows the ordered reference set without substituting identity.
- `temporalCoherence`: adjacent shots preserve appearance and scene state without unexplained drift.
- `artifactFreedom`: hands, faces, text, geometry, flicker, and transitions are usable.

Each score record must include `shotId`, `outputAssetId`, `scores`, `notes`, and `failures`. Acceptance requires every required dimension to score at least 4 for every shot, no unresolved failure tagged `identity_swap`, `reference_ignored`, `scene_drift`, `temporal_discontinuity`, or `unsafe_output`, and a human reviewer decision. Raw outputs, manifests, prompts, reference provenance, and the immutable entity-usage snapshots must be retained with SHA-256 digests.

Local deterministic fixtures may validate ordering, persistence, schema shape, and failure handling, but cannot satisfy visual acceptance. Provider selection, credentials, call count, cost ceiling, staging deployment, and real-media generation remain behind E-01 explicit approval.
